# Signal 饮品情报工作台 · 交互 demo

目标：验证个人 FDE 作品的“导入 → 建议 → 人工复核 → 报告”业务闭环。
已确认：用户需要可以操作的 demo；正式产品方案仍在讨论。
假设：内置 50 条“模拟公共模式”样本，使用真实茶饮品牌名称与公开活动结构作演示，标题、正文、点赞和账号均为合成数据，不代表品牌事实；AI 由本地关键词规则模拟，不调用模型、不上传数据；同一份数据的复核状态保存在当前浏览器，点击重置演示才清除。
范围：CSV 导入、错误提示、建议证据、动作名称和分类编辑、排除/确认、复核状态本地保留、已确认结果锁定/解锁、审计记录、报告筛选、动作详情、Word 报告和 CSV 明细导出。
复用：PapaParse、tools/import-beverage-data.cjs 的校验与聚合。原站资源没有作为页面资产使用。
验收：建议结果未复核不得发布；修改或重新导入使旧报告失效；已排除帖子不计入报告；可从汇总追溯帖子。
启动：在项目根目录运行 `rtk npm start`，访问 http://127.0.0.1:4173 。仅绑定本机。
界面：已收敛为 C 提案式方案，作为当前唯一 UI 基线；后续功能完善后再评估是否引入新的视觉方向。复核完成后默认锁定，需显式解锁才能修改。
待讨论：复核粒度是否顺手；首页是否应优先呈现报告；真实 AI 的输出与评估口径。
没有历史周样本，因此不展示伪造跨周变化或节省工时。跨周、XLSX直读、持久化和自动采集不在本 demo 内。
